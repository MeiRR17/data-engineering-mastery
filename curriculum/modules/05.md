# שלב 05: Data Modeling & Analytics Engineering

**רמת יעד:** Foundation מקצועי במידול נתונים (אינו הסמכה רשמית)  
**שלב קדם:** Stage 04 — PostgreSQL / RLS  
**תוצר:** Star Schema קטן עם SCD Type 2, Fact בטוחה ל־Replay ו־Daily Metrics מאומתים.

## מתחילים כאן

[**מעבדת Stage 05 המעשית**](../../labs/05-modeling/README.md) · [רובריקת הערכה](../../docs/ASSESSMENT.md) · [DataPulse](../../projects/datapulse/README.md)

### רצף למידה

1. למד Grain, Natural Key לעומת Surrogate Key, Fact/Dimension, SCD Type 1/2, UTC לעומת זמן מקומי.
2. נבא כמה שורות יחזיר Join בין אירועים לממד שיש לו שתי גרסאות לאותו Business Key.
3. בצע את המעבדה ב־PostgreSQL על נתונים סינתטיים; השלם UPSERT למודל Fact ו־View של Metrics.
4. הרץ בדיקות גרעיניות, SCD2, NULL, Double Counting ו־Replay.
5. הסבר כיצד בחירת מודל משתנה כאשר המקור מתעדכן באיחור.
6. ציין מגבלות: הריפו עדיין אינו מכיל פרויקט dbt מאומת, טעינת SCD2 אוטומטית או פריסת ענן של שלב זה.

~~~bash
python3 labs/05-modeling/run_lab.py --reference
python3 labs/05-modeling/run_lab.py
~~~

ההרצה הראשונה בודקת פתרון ייחוס. השנייה אמורה להיכשל עד שתיישם את המשימה; שמור ראיות לתהליך התיקון.

### משימות חובה

- [ ] להגדיר Grain לכל טבלה ולשרטט Lineage (מקור → Dimension/Fact → Metric).
- [ ] לבצע Join לפי תוקף היסטורי של גרסת ממד ולהימנע מ־Fan-out.
- [ ] ליצור Mart עם ספירת אירועים, ספירה עם ערכי מגניטודה וממוצע שמתחשב ב־NULL.
- [ ] להוכיח שבניית המודל מחדש אינה מייצרת כפילויות.
- [ ] להוכיח שתיקון מקור מאוחר משנה את המדדים בלי לאבד היסטוריה.
- [ ] להשלים מבחן העברה על נתון חדש ולצרף PR עם פלט בדיקות מסונן.

### מבחן עצמאי (ללא AI)

1. מדוע מזהה אזור עסקי אינו בהכרח Primary Key תקין בטבלת SCD2?
2. מה הסיכון שבהצמדת אירוע לגרסת הממד העדכנית במקום לגרסה התקפה בזמן האירוע?
3. מה יקרה לממוצע אם נחליף NULL באפס?
4. אילו שתי בדיקות היית מוסיף כדי לזהות מקור עם שיוך חסר לאזור?
