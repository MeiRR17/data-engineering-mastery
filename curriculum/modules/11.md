# Stage 11 — Streaming, Kafka and Consumer Offsets

**Track:** Advanced  
**Prerequisite:** 10  
**Outcome:** A transactional local sink/offset lab and an optional real single-node Kafka producer/consumer exercise.

[Guided notebook](../../notebooks/11_streaming_offsets.ipynb) · [Hands-on lab](../../labs/11-streaming/README.md) · [Assessment rubric](../../docs/ASSESSMENT.md) · [Full roadmap](../../README.md)

## Why this matters

- Topic/partition/offset identity vs business event ID.
- At-least-once delivery, lost acknowledgements and idempotent upserts.
- Late-event watermarks, poison records and reason-only dead letters.
- Broker offset commits and consumer restart/rebalance behavior.

The goal is not to memorize tool commands. You must predict the output, write your own code, intentionally reproduce a failure, repair it, and explain the operational tradeoffs.

## Learning workflow

1. Open the guided notebook **visually** in VS Code, predict each assertion, then run its code cells. Use [the VS Code setup guide](../../docs/VS-CODE-LEARNING-SETUP.md) if the notebook opens as JSON.
2. Read the official documentation linked in the notebook or lab and sketch the data flow.
3. Run the instructor grader only to confirm the teaching exercise itself works:

~~~bash
python3 labs/11-streaming/grade.py --reference
~~~

4. Run the learner grader and implement the unfinished starter. It is **expected to fail at first**:

~~~bash
python3 labs/11-streaming/grade.py
~~~

5. Add tests, investigate one injected failure, record sanitized results and open a learner PR. Use AI for hints or code review after attempting the solution, not as a substitute for an independent exam.

## Required tasks

- [ ] Implement the three learner functions and pass 25 local failure tests.
- [ ] Inject a crash before/after a transaction and compare checkpoint behavior.
- [ ] On suitable hardware, run the real Kafka broker loopback demo.
- [ ] Defend limitations of cross-system exactly-once and propose a corrected-late-data policy.

## Independent conceptual check (without AI)

1. Why does committing a SQLite transaction not atomically commit a Kafka offset?
2. How do retry, replay, dead-letter routing and rebalance differ?

## Exit gate

Pass all 25 student tests and submit a new recovery case; broker operations require separate real broker evidence.

You must also document assumptions, reproducible commands, risks and an original transfer scenario in your PR. No credentials, private data or unauthorized writes are permitted. Passing instructor CI does not certify a learner or prove production deployment.
