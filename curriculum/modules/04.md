# Stage 04 — PostgreSQL Security, Migrations and Supabase

**Track:** Core  
**Prerequisite:** 03  
**Outcome:** An isolated PostgreSQL 17 migration, RLS negative/positive tests, replay and atomic rollback.

[Guided notebook](../../notebooks/04_postgres_security.ipynb) · [Hands-on lab](../../labs/04-postgres/README.md) · [Assessment rubric](../../docs/ASSESSMENT.md) · [Full roadmap](../../README.md)

## Why this matters

- Schemas, migrations and database roles.
- GRANT vs row-level security, private raw schemas and view privileges.
- Anonymous/authenticated access denial and safe key boundaries.
- Supabase as an optional owner-approved sandbox, not a prerequisite for local training.

The goal is not to memorize tool commands. You must predict the output, write your own code, intentionally reproduce a failure, repair it, and explain the operational tradeoffs.

## Learning workflow

1. Open the guided notebook **visually** in VS Code, predict each assertion, then run its code cells. Use [the VS Code setup guide](../../docs/VS-CODE-LEARNING-SETUP.md) if the notebook opens as JSON.
2. Read the official documentation linked in the notebook or lab and sketch the data flow.
3. Run the instructor grader only to confirm the teaching exercise itself works:

~~~bash
python3 labs/04-postgres/run_lab.py --reference
~~~

4. Run the learner grader and implement the unfinished starter. It is **expected to fail at first**:

~~~bash
python3 labs/04-postgres/run_lab.py
~~~

5. Add tests, investigate one injected failure, record sanitized results and open a learner PR. Use AI for hints or code review after attempting the solution, not as a substitute for an independent exam.

## Required tasks

- [ ] Use Docker to run the temporary PostgreSQL lab on synthetic data.
- [ ] Verify unauthenticated users cannot access sensitive tables or write curated data.
- [ ] Test migration replay, source updates and transaction rollback.
- [ ] Write a cloud deployment plan with secrets and budget controls; deploy only with separate authorization.

## Independent conceptual check (without AI)

1. Why is a publishable key different from a secret service-role key?
2. Why is RLS not the same control as GRANT?

## Exit gate

Pass actual disposable PostgreSQL permission and RLS tests, and record why these are not proof of cloud deployment.

You must also document assumptions, reproducible commands, risks and an original transfer scenario in your PR. No credentials, private data or unauthorized writes are permitted. Passing instructor CI does not certify a learner or prove production deployment.
