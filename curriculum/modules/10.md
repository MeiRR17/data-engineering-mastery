# Stage 10 — Big Data, Spark and Distributed Data Semantics

**Prerequisites:** Stage 09 release engineering; knowledge of SQL aggregation, event time, UTC, idempotency and data-quality gates.  
**Learning artifact:** an independently graded partitioned reducer plus a real `local[2]` Spark DataFrame transformation.

[**Open the full Stage 10 lab**](../../labs/10-spark/README.md) · [Assessment rubric](../../docs/ASSESSMENT.md)

## Learning workflow

1. Read about **DAG execution, partitioning, Wide vs Narrow transformations, Shuffle, Skew and Window-based deduplication**.
2. Predict which records will survive a late source update and what timezone conversion will do to daily metrics.
3. Run `python3 labs/10-spark/grade.py --reference`, then implement the learner starter and pass the **21 Light mode tests**.
4. On a computer with Java 17+ and pinned PySpark, run the Spark plan, compare its output with Light mode, and pass **9 Spark tests** on the instructor reference.
5. Implement the learner's Spark `build_mart` without collecting input data to Python. Trigger and observe a failing test when dedup is removed, then fix it.
6. Inspect `spark_pipeline.py --explain` and run `skew_demo.py`. Explain the partition load imbalance.
7. Record a short ADR: when is Spark justified compared with ordinary SQL or DuckDB? How would you benchmark fairly?

## Useful commands

~~~bash
python3 labs/10-spark/grade.py --reference

# Optional full mode after installing Java 17 and pyspark==4.0.5:
python3 labs/10-spark/spark_pipeline.py --partitions 2 --explain
python3 labs/10-spark/spark_grade.py --reference
python3 labs/10-spark/spark_grade.py
python3 labs/10-spark/skew_demo.py
~~~

The commands without `--reference` intentionally fail until the learner completes the exercise. No cloud account is required.

## Exit criteria

- [ ] Light reference tests pass and learner implements a correct 21-scenario solution.
- [ ] Learner explains UTC, NULL, latest-update and tie-breaking semantics independently.
- [ ] Spark full-mode executes on a real local JVM, or the learner explicitly records that full mode is deferred due to hardware.
- [ ] Learner can explain an Exchange and a skewed partition without assuming small benchmarks generalize to production.
- [ ] Student provides a PR, sanitized test evidence, a new edge-case test and a no-AI transfer explanation.

**Not verified by this lab:** distributed physical cluster, streaming/Kafka, Parquet data lake, controlled DuckDB benchmark or any professional certification. These remain later tasks; completing Light mode alone is not proof of Spark proficiency.
