# Stage 09 — CI/CD, Reproducible Releases and Rollback

**Track:** Advanced  
**Prerequisite:** 08  
**Outcome:** Deterministic ZIP release artifacts, integrity checks and simulated environment promotion/recovery.

[Guided notebook](../../notebooks/09_releases_rollback.ipynb) · [Hands-on lab](../../labs/09-cicd/README.md) · [Assessment rubric](../../docs/ASSESSMENT.md) · [Full roadmap](../../README.md)

## Why this matters

- Continuous Integration vs Delivery vs Deployment.
- Versioned reproducible builds and SHA-256 manifests.
- Allowlisted ZIP members and rejecting tampered artifacts.
- Health gates, atomic pointer promotion and verified rollback.

The goal is not to memorize tool commands. You must predict the output, write your own code, intentionally reproduce a failure, repair it, and explain the operational tradeoffs.

## Learning workflow

1. Open the guided notebook **visually** in VS Code, predict each assertion, then run its code cells. Use [the VS Code setup guide](../../docs/VS-CODE-LEARNING-SETUP.md) if the notebook opens as JSON.
2. Read the official documentation linked in the notebook or lab and sketch the data flow.
3. Run the instructor grader only to confirm the teaching exercise itself works:

~~~bash
python3 labs/09-cicd/grade.py --reference
~~~

4. Run the learner grader and implement the unfinished starter. It is **expected to fail at first**:

~~~bash
python3 labs/09-cicd/grade.py
~~~

5. Add tests, investigate one injected failure, record sanitized results and open a learner PR. Use AI for hints or code review after attempting the solution, not as a substitute for an independent exam.

## Required tasks

- [ ] Build the same version twice and prove identical hashes.
- [ ] Reject a changed ZIP or manifest before release.
- [ ] Simulate a crash before promotion; prove the old release remains active.
- [ ] Explain expand/backfill/contract migrations and why rollback can be destructive.

## Independent conceptual check (without AI)

1. Why is a SHA-256 checksum not proof of artifact authorship?
2. How do code rollback and schema/data rollback differ?

## Exit gate

Pass 26 local release/fault tests, produce a release note and demonstrate health-gated rollback.

You must also document assumptions, reproducible commands, risks and an original transfer scenario in your PR. No credentials, private data or unauthorized writes are permitted. Passing instructor CI does not certify a learner or prove production deployment.
