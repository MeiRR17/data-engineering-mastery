# Stage 09 — פריסה מבוקרת, CI/CD ושחזור Releases

**שלב קדם:** Stage 08 — API, Data Serving ו־Dashboard.  
**תוצר:** בנייה שחזורית של חבילת Release, אימות שלמות SHA-256, קידום בטוח בין סביבות מדומות ו־Rollback.

[**מעבדת Stage 09**](../../labs/09-cicd/README.md) · [רובריקת הערכה](../../docs/ASSESSMENT.md)

## מה נלמד?

1. ההבדל בין CI, Continuous Delivery ו־Continuous Deployment, וההבדל בין Build Artifact לבין סביבת הרצה.
2. כיצד ליצור Release שחזורי עם Version ו־Digest, ולוודא שלא נעשה שינוי לאחר הבנייה.
3. למה SHA-256 אינו חתימה קריפטוגרפית או הוכחת מקור מהימן.
4. איך לבודד Dev, Staging ו־Production מבחינת הרשאות, סודות ותעבורה.
5. כיצד לבצע Health Gate לפני Promotion, ולשמור גרסה אחרונה תקינה במקרה של תקלה.
6. כיצד מתכננים Expand/Contract Migration ולמה Rollback של Schema אינו זהה ל־Rollback של קוד.

## מה עושים עכשיו?

~~~bash
python3 labs/09-cicd/grade.py --reference
python3 labs/09-cicd/demo.py
python3 labs/09-cicd/grade.py
~~~

הבדיקה האחרונה **צפויה להיכשל בתחילת הלמידה** מפני ש־`starter.py` אינו פתור. הלומד מממש בעצמו חמש פונקציות וצריך לעבור 26 בדיקות התנהגות, כשל ו־Tampering. כל הפעולות בסביבת קבצים מקומית זמנית בלבד; אין פריסה אמיתית לענן.

## משימות להגשה

- [ ] Build חוזר של אותה גרסה מניב את אותו SHA-256.
- [ ] קובץ שעבר שינוי או Manifest שגוי נחסם.
- [ ] שום Payload בלתי צפוי אינו נכנס לארכיון.
- [ ] פריסה לסביבה אחת אינה משנה את האחרות.
- [ ] כשל Health או Crash לפני Promotion משאיר גרסה קיימת פעילה.
- [ ] Rollback מאמת את קובץ היעד לפני מעבר.
- [ ] תכננת Expand/Backfill/Contract Migration עם סיכוני תאימות.
- [ ] הגשת PR, יומן בדיקות מסונן, Release Note ו־ADR עם מגבלות.

**הגבלת היקף:** זו הכשרה במושגי CI/CD, לא פריסת Production אמיתית. אין כאן Kubernetes, OIDC, קונפיגורציית ענן, מנגנון Credentials, ניטור או הפעלת Migration בלתי הפיך. תעודת הסמכה תדרוש ראיות נוספות.
